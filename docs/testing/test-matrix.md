## Determinism, isolation and execution

Domain and failure-boundary contracts use injected runtimes, fixed timestamps, sequential identifiers and `MemoryStorage`. Tests inject failures or controlled promises rather than making behavior randomly succeed or fail. Credential salt generation remains cryptographic production behavior; tests assert its security properties rather than comparing random salt bytes. UI fixtures use stable sample identifiers and synthetic customer details; adapters create normal references during actual workflows.

Component tests clean up mounted trees; storage-dependent interactions clear their browser stores before each case or supply fresh in-memory stores. The integration lifecycle creates its own persistence instances. Playwright creates a fresh browser context per test. Controlled expiry and coupon-boundary tests advance injected time instead of sleeping. Browser readiness uses observable headings, field states, totals, navigation and persisted results rather than arbitrary delays.

The default unit runner includes `src/**/*.test.*`, `tests/unit`, `tests/contracts` and `tests/integration`. A full run must report executed files/cases, with skipped, todo, expected-failure or exclusive cases separately identified. No skipped, todo, expected-failure or exclusive declarations were found in this audit; a runner failure must still be investigated and corrected before completion is recorded.

The configured [CI workflow](../../.github/workflows/ci.yml) performs frozen install, formatting, lint, strict TypeScript, Vitest, production build and Chromium Playwright, retaining browser artifacts on failure. Local verification of these commands is not evidence that a remote GitHub Actions run passed. Browser source presence, a passing build and route inventory are also not substitutes for a completed journey.

Reproduce the consolidated non-browser checks with:

```sh
npm ci
npm run format:check
npm run lint
npm run typecheck
npm test -- --run
npm run build
```

Run `npm run test:e2e` after installing the configured Playwright browser. A managed environment may use the documented Chromium executable override. Final browser-engine, production preview, performance and DRF handoff evidence belongs to TASK-038–040 and is recorded in the progress tracker when actually performed.
